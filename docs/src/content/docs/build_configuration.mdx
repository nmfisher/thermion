## Render with FilamentApp

`ThermionViewer` manages a scene for you. Its `app` is a `FilamentApp`, the
Dart interface to the Filament renderer. Use it to create multiple views,
scenes, or render targets with their own lifetimes.

```dart
final app = viewer.app;
final view = await app.createView(createScene: true);

// Use the view, then release it when finished.
await app.destroyView(view);
```

Destroy the views, scenes, swap chains, textures, and other resources your
code creates. A viewer owns its own scene resources.

### Headless rendering

Use `createHeadlessSwapChain` to render without a window. For an image you can
read back, create a render target and attach it to a view. The
[headless Dart example](https://github.com/nmfisher/thermion/tree/develop/examples/dart/cli_headless)
shows the complete flow, from creating the engine to saving the image.

## Compile a custom material at build time

Write a Filament `.mat` file and point Thermion at it in your app's
`pubspec.yaml`. Thermion will compile it to a `.filamat` file with the matching
Filament compiler.

```yaml
hooks:
  user_defines:
    thermion_dart:
      material_compilation:
        inputs:
          - materials/paint.mat
        output: assets/materials
```

This produces `assets/materials/paint.filamat`. Create the output directory
and list `assets/materials/` under `flutter.assets` in a Flutter app. Use
`rootBundle` from `package:flutter/services.dart` to load the file. In a
native Dart tool, read its bytes from disk.

```dart
final data = await rootBundle.load('assets/materials/paint.filamat');
final material = await viewer.app.createMaterial(
  data.buffer.asUint8List(data.offsetInBytes, data.lengthInBytes),
);
final paint = await material.createInstance();
await asset.setMaterialInstanceForAll(paint);
```

`inputs` accepts file paths, directories, and globs relative to the app root.
The first build downloads the tools and compiles the materials. Later builds
reuse the output until a source, include, or compiler changes.

Use `backends: all` (the default) to ship shaders for Metal, Vulkan, OpenGL,
and WebGPU in one file. Use `native` for Metal, Vulkan, and OpenGL, or `web`
for WebGL2 and WebGPU. You can also list individual compiler targets such
as `[vulkan]`. Choose the targets your app will use.

You can also compile a `.mat` directly with a version-matched `matc`. For
embedding material bytes in a native library, see
[generated C assets and build internals](https://github.com/nmfisher/thermion/blob/develop/docs/material-build-internals.md).

## Compile a material at runtime

If your app generates shaders or lets users edit them, add
`runtime_materials: true` under `hooks.user_defines.thermion_dart` in
`pubspec.yaml`. At startup, check `FilamentApp.runtimeMaterialsSupported`
before calling the compiler.

```dart
final material = await viewer.app.compileMaterialSource(
  'red',
  '''
  void material(inout MaterialInputs material) {
    prepareMaterial(material);
    material.baseColor.rgb = float3(1.0, 0.0, 0.0);
  }
  ''',
  shading: MaterialShading.lit,
);
```

Use `compileMaterialPackage` for a full `.mat` with a configuration block,
parameters, or vertex code. Pass named include files in its `includes` map.
The compiler resolves includes by name from that map.

Runtime compilation adds to your app's size and can take hundreds of
milliseconds. On the web it runs inline and requires the WebGL2 runtime-materials
engine. WebGPU and hybrid builds use precompiled materials.
See [Run on the web](/web/#choose-a-backend) and the
[material editor example](https://github.com/nmfisher/thermion/tree/develop/examples/dart/material_editor).

## Include the built-in materials you use

Enable built-in helpers used by your app under `materials`. For example,
a transform gizmo uses `gizmo` and a background image uses `image`. A scene
that only uses materials supplied by its glTF files can omit this setting.

```yaml
hooks:
  user_defines:
    thermion_dart:
      materials:
        gizmo: true
        image: true
```

By default, iOS and macOS include Metal shaders. Android, Linux, and Windows
include Vulkan and OpenGL. To limit what your app ships on a target, list
its backends under `materials.backends`.

```yaml
hooks:
  user_defines:
    thermion_dart:
      materials:
        gizmo: true
        backends:
          android: [opengl, vulkan]
          windows: [vulkan]
```

A device needs at least one of the listed backends to render those materials.
Omitted platforms keep their defaults. Use `backend: webgpu` to select native
WebGPU. A matching `materials.backends` setting takes precedence for the
material variant. Use [Web backend settings](/web/#choose-a-backend) for browsers.

## Debug a native build

Flutter's debug mode still uses Thermion's release libraries by default.
To use the debug libraries and turn on tracing, add these settings to
`pubspec.yaml`.

```yaml
hooks:
  user_defines:
    thermion_dart:
      mode: debug
      tracing: enabled
```

If Flutter keeps using the old settings, run `flutter clean` and rebuild.
An upstream Filament issue currently prevents Android debug libraries from
working. Use release libraries on Android.

### Native error handling

A Filament panic stops the process. Dart can handle ordinary Dart exceptions
and failed futures. Native plugins that link Filament need compatible C++ build
settings, including disabled C++ exceptions.

## Work on Thermion itself

Follow the [repository's contributor guide](https://github.com/nmfisher/thermion/blob/develop/CONTRIBUTING.md)
if you're changing Thermion's C++ code or rebuilding its bundled materials.
To use a locally built browser engine, see [Build the engine locally](/web/#building-the-wasm-locally).
`skip_native_build: true` is available for pure Dart tools that need to skip
the native C++ build.
