Thermion uses a prebuilt WebAssembly engine in the browser. The build hook
copies `thermion_dart.js` and `thermion_dart.wasm` into your app's `web/`
directory.

## Quick start

Run or build your Flutter app for the web as usual:

```bash
flutter run -d chrome
# or
flutter build web
```

Serve the app with the headers in [Cross-origin isolation](#cross-origin-isolation).

## Choose a backend

WebGL2 is the default. To select the engine and built-in material variants
for your Dart or Flutter web app, set `backend.web` in the app's
`pubspec.yaml`.

```yaml
hooks:
  user_defines:
    thermion_dart:
      backend:
        web: webgpu
```

| `backend.web` | Renderers available | Backend to pass at startup |
| --- | --- | --- |
| `webgl2` | WebGL2 | `Backend.OPENGL` |
| `webgpu` | WebGPU | `Backend.WEBGPU` |
| `hybrid` | WebGL2 and WebGPU | Choose either |

The build setting selects what the app ships. The runtime setting selects the
renderer when you create the engine. Use `hybrid` to make that choice at
startup and compile any [custom materials](/materials/#building-custom-materials)
for both backends.

The WebGPU-capable engine runs on the browser's main thread and uses precompiled
materials. Use the WebGL2 runtime-materials variant if your app needs to
[compile materials at runtime](/materials/#compiling-materials-at-runtime).

### Dart

Import `package:thermion_dart/thermion_dart.dart` and
`package:thermion_dart/src/filament/src/implementation/ffi_filament_app.dart`.
Pass the backend when creating the engine, after loading `thermion_dart.js`
and initializing the bindings.

```dart
await FFIFilamentApp.create(
  config: FFIFilamentConfig(backend: Backend.WEBGPU),
);
```

### Flutter

Import `package:thermion_flutter/thermion_flutter.dart`. In `main()`, set
the backend before calling `runApp()` or creating a Thermion viewer.

```dart
ThermionFlutterPlugin.instance.setOptions(
  const ThermionFlutterOptions(
    webOptions: WebOptions(backend: Backend.WEBGPU),
  ),
);
```

For a `hybrid` build, Flutter's `WebGpu.isSupported()` can help choose a
renderer at startup. It checks whether the browser exposes WebGPU. Rendering
with WebGPU also requires a usable GPU device.

## Cross-origin isolation

Thermion's browser engines use shared WebAssembly memory. Serve your app with
COOP and COEP headers to enable `SharedArrayBuffer`.

For local runs, pass them on the command line:

```bash
flutter run -d chrome \
  --web-header=Cross-Origin-Opener-Policy=same-origin \
  --web-header=Cross-Origin-Embedder-Policy=require-corp
```

For production, set the headers on your host. On Cloudflare Pages, add a `web/_headers`
file:

```
/*
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Embedder-Policy: require-corp
  Cross-Origin-Resource-Policy: cross-origin
```

## Pre-fetching the artifacts

To fetch the engine ahead of time, pass the same backend you plan to use in
your app.

```bash
dart run thermion_dart:download_web --backend webgpu
```

Use `webgl2` or `hybrid` for the other choices. The command writes to `web/`
by default. Use `-o` to choose another directory.

## Building the WASM locally

Building the WASM yourself is only needed if you're modifying Thermion's native C++ and
want to test on web without bumping the pinned version and waiting for CI to rebuild the
R2 artifacts.

Build the emscripten target locally and opt in via your app's `pubspec.yaml`:

```yaml
hooks:
  user_defines:
    thermion_dart:
      web_local: true
```

```bash
# from thermion_dart/native/web/build:
emcmake cmake ..
emmake make

flutter run -d chrome
```

With `web_local` set, the build hook copies `thermion_dart.{js,wasm}` from your local
`thermion_dart/native/web/build/build/out/` instead of downloading from R2. Remove the
flag (or set it to `false`) to go back to the pinned prebuilt.
