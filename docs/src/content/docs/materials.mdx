Thermion uses Filament's material system. A **material** is a shader program
compiled from a `.mat` file; a **material instance** is a runtime binding of
parameters to that material. Every renderable entity has one or more material
instances.

## Built-in materials

`FilamentApp.instance` (the shared engine facade) can create a couple of
ready-to-use material instances without compiling anything:

```dart
final unlit = await FilamentApp.instance!.createUnlitMaterialInstance();
final lit   = await FilamentApp.instance!.createUbershaderMaterialInstance();
```

- **Unlit** — flat-shaded, ignores lighting. Good for UI overlays and debug
  geometry.
- **Ubershader** — the full PBR lit material (the default glTF material).

## Setting parameters

Material instances expose typed setters for shader parameters:

```dart
await material.setParameterFloat4("baseColorFactor", 0.0, 1.0, 0.0, 1.0); // RGBA green
await material.setParameterInt("baseColorIndex", -1);   // -1 = use baseColorFactor, not a texture
await material.setParameterFloat("metallic", 0.8);
await material.setParameterBool("doubleSided", true);
```

## Swapping materials on an asset

A loaded glTF asset exposes its material instances, and you can replace them:

```dart
// Read the current instance at primitive 0
final current = await asset.getMaterialInstanceAt();

// Replace the material on every primitive
await asset.setMaterialInstanceForAll(unlit);

// Or replace at a specific primitive index
await asset.setMaterialInstanceAt(unlit);
```

:::note
Materials that need extra vertex attributes — **wireframe** (barycentric
coordinates), **stencil highlight outlines**, and **flat shading** — only
work on assets loaded with `loadGltf(..., rebuildVertices: true)`, which
rebuilds vertex buffers with a superset of attributes at the cost of ~3x
vertex memory. `setFlatShading` and `setStencilHighlight` **throw** if the
asset wasn't loaded this way.
:::

## Textures

Load an image, create a sampler, and bind both to a material parameter:

```dart
final image = await FilamentApp.instance!.decodeImage(byteData);
final texture = await FilamentApp.instance!.createTexture(...);

final sampler = TextureSampler(
  minFilter: SamplerFilterParams.linear(),
  magFilter: SamplerFilterParams.linear(),
);

await material.setParameterInt("baseColorIndex", 0); // use the texture
await material.setParameterTexture("baseColorMap", texture, sampler);
```

Remember to `dispose()` textures, samplers, and `LinearImage`s when you're done
with them to avoid GPU memory leaks.

## Procedural geometry

You don't need a glTF file to render something. `viewer.createGeometry` builds
a renderable from a `Geometry` and a list of material instances:

```dart
final asset = await viewer.createGeometry(
  CubeGeometry.cube(),
  materialInstances: [unlit],
);
```

Built-in geometries include `CubeGeometry`, `SphereGeometry`,
`CylinderGeometry`, `ConeGeometry`, `CapsuleGeometry`, `PyramidGeometry`,
`QuadGeometry`, and `PlaneGeometry`.

## Building custom materials

For custom shaders, write a Filament `.mat` file and compile it with the
Filament material compiler (`matc`/`uberz`).

### Automatic recompilation in the build hook

Thermion's bundled materials are (re)compiled automatically by the Dart
build hook on your development machine — you no longer need a local
Filament build or a manual `make materials` step when Thermion bumps its
Filament version.

The flow, per native (non-web) build:

1. The hook reads the pinned Filament version (`filament.version`) and
   downloads the matching `matc`/`resgen` binaries for the **host**
   platform from Thermion's R2 release bucket. Only the `bin/` entries of
   the release zip are extracted. These tools are built with
   WebGPU support, so all backend variants (Metal, Vulkan, OpenGL, WebGPU)
   can be compiled.
2. Every bundled `.mat` source under `thermion_dart/materials/` is compiled
   into the eight per-backend variants, exactly as `make materials` does.
   The output lands in a cache — it never touches your project.
3. A fingerprint over `filament.version`, the `.mat` sources, the host
   platform and the variant table is recorded in a `manifest.json` next to
   the output. When the fingerprint still matches, later builds skip the
   download and the compilation entirely (a Filament bump or a `.mat` edit
   invalidates it automatically).

Cache locations:

- **Tools** (`matc`/`resgen`): `$XDG_CACHE_HOME` or `~/.cache`, under
  `thermion/filament-tools/filament-<version>-webgpu-<host>` — shared by
  all projects on the machine, downloaded once per Filament version.
- **Generated materials**: `<thermion_dart package>/.dart_tool/thermion_dart/materials/<version>/material`,
  layout-identical to the committed `native/include/material/` tree.

Failure behaviour: if the tools cannot be downloaded (e.g. no network) or
`matc` fails its WebGPU smoke test, the hook logs a prominent warning and
**falls back to the committed material artifacts** shipped with the
package. Those are regenerated by Thermion CI on every Filament bump, so
this fallback is always safe for released versions — only local `.mat`
edits would be missed, and the warning says so. A build never sees a
half-written artifact set: output is staged and swapped in atomically.

### Opting out

Add this to your app's `pubspec.yaml` to skip the automatic compilation and
always use the committed artifacts:

```yaml
hooks:
  user_defines:
    thermion_dart:
      compile_materials: false
```

(User defines must go in the *consuming* package's `pubspec.yaml`; the hook
runs with a curated environment, so command-line defines and environment
variables are not forwarded to it.)

### Refreshing the committed artifacts (maintainers)

From the repository root:

```
make materials
```

This requires the `FILAMENT_PATH` environment variable to point at a local
Filament build's `out/release/bin` (see the [Filament](/filament/) page) —
or use `scripts/regenerate-materials.sh`, which downloads the
version-matched tools from R2 exactly like the build hook does.
Existing material sources live in `thermion_dart/materials/` (e.g.
`image.mat`, `grid.mat`, `silhouette.mat`).

> A runnable example covering material swapping, parameter setting, and texture
> binding is in `examples/flutter/materials_and_textures`.
