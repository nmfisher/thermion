Use `ThermionViewer` when you want to control a scene yourself. This guide shows
the scene code behind a Flutter viewport. Start with
[Show your first model](/quickstart/) for package and asset setup.

## Load and display a model

Create the viewer once for the lifetime of the screen. Load the model, move
the camera back so it can see the model at the origin, and add a light.

```dart
import 'package:thermion_flutter/thermion_flutter.dart';

Future<ThermionViewer> createScene() async {
  final viewer = await ThermionFlutterPlugin.createViewer();
  try {
    await viewer.loadGltf('assets/model.glb');
    final camera = await viewer.getActiveCamera();
    await camera.lookAt(Vector3(0, 1, 5));
    await viewer.addDirectLight(DirectLight.sun());
    return viewer;
  } catch (_) {
    await viewer.dispose();
    rethrow;
  }
}
```

<span id="3-render-it-with-thermionwidget"></span>
<span id="7-run-it"></span>

Put `ThermionWidget.create` in your Flutter widget tree. The widget calls
your factory when the platform is ready and disposes the viewer when the
widget is removed.

```dart
ThermionWidget.create(viewerFactory: createScene)
```

A loaded model is a `ThermionAsset`. Its root entity holds the model's transform,
and its children represent parts like meshes and bones. Keep the returned asset
if you want to move it or animate it later.

Flutter paths are relative to the asset bundle. Use a `file://` URI for local
files in a native Dart app. For `.gltf` files with external textures or buffers,
keep those files next to the model or pass `resourceUri` to tell Thermion where
to look.

<span id="positions-and-movement"></span>

## Move or resize a model

Use the `asset` returned by `loadGltf`. `setTransform` takes the complete
position, rotation, and scale as a `Matrix4`. For a relative movement, read the
current transform and add the offset before writing it back.

```dart
await asset.setTransform(Matrix4.translation(Vector3(0, 1, 2)));

final transform = await asset.getLocalTransform();
transform.translateByVector3(Vector3(0, 0.5, 0));
await asset.setTransform(transform);
```

<span id="hierarchy"></span>
<span id="querying-an-asset"></span>

### Work with parts of a model

Use `getChildEntityNames()` to see named parts and `getChildEntity('Wheel')` to
find one. Pass a child handle as `entity:` to `setTransform` to move that part.
Use `viewer.app.setParent(child, parent)` to make one entity follow another.

`asset.getBoundingBox()` reads the model's bounds. `asset.transformToUnitCube()`
fits it inside a unit cube when the root has valid renderable bounds. If you
already know the correct bounds, pass them to
`viewer.app.transformManager.transformToUnitCube(asset.entity, bounds)`.

<span id="gpu-instancing"></span>

### Make many copies

Pass `initialInstances` to `loadGltf` to allocate copies up front. Each copy
shares the source model's geometry and can have its own transform.

```dart
final rocks = await viewer.loadGltf('assets/rock.glb', initialInstances: 100);
for (var i = 0; i < 100; i++) {
  final rock = await rocks.getInstance(i);
  await rock.setTransform(Matrix4.translation(Vector3(i * 2.0, 0, 0)));
}
```

Use `createInstance()` to add copies later. Keep `releaseSourceData` disabled
if you plan to do that.

## Draw something without a model file

Pass a shape to `createGeometry`. This unlit cube stays visible without a light.
Use the built-in sphere, plane, or cylinder the same way.

```dart
final unlit = await viewer.app.createUnlitMaterialInstance();
final cube = await viewer.createGeometry(
  CubeGeometry.cube(),
  materialInstances: [unlit],
);
```

<span id="camera-basics"></span>

## Move and aim the camera

Get the current camera and call `lookAt`. Coordinates use `+Y` for up and `-Z`
for forward. Pass `focus:` to look away from the origin.

```dart
final camera = await viewer.getActiveCamera();
await camera.lookAt(Vector3(0, 1, 5), focus: Vector3(0, 0.5, 0));
```

Create another camera with `viewer.createCamera()` and make it active with
`viewer.setActiveCamera(camera)`.

<span id="wiring-input-to-a-widget"></span>

## Let users orbit the model

If your screen already owns a viewer, create an input handler from it.
Put `ThermionListenerWidget` around the viewport to forward Flutter's pointer,
touch, scroll, and keyboard events to that handler.

```dart
final input = DelegateInputHandler.fixedOrbit(viewer, minimumDistance: 0.1);
```

```dart
ThermionListenerWidget(
  inputHandler: input,
  child: ThermionWidget(viewer: viewer),
)
```

<span id="sensitivity"></span>
<span id="custom-controls"></span>

Use `DelegateInputHandler.flight(viewer)` for free movement. Pass
`InputSensitivityOptions` to tune the built-in controls, or supply your own
`InputHandlerDelegate` for custom pointer and keyboard behavior.

<span id="gltf-animations"></span>

## Play a glTF animation

If the model contains animations, call `getGltfAnimationNames()` to see what's
available. This plays the first clip and repeats it.

```dart
final names = await asset.getGltfAnimationNames();
if (names.isNotEmpty) {
  await asset.playGltfAnimation(0, loop: true);
}
```

When your app owns the animation clock, as in the headless example,
pass an increasing frame timestamp in nanoseconds to
`viewer.app.animationManager.update(frameTimeInNanos)`.
Call `stopGltfAnimation(0)` to stop, or `setGltfAnimationTime(index, seconds)`
to jump to a point in a clip.

<span id="notes"></span>
<span id="animations-when-backgrounded"></span>

Pause animation updates when your app is backgrounded. Queueing animation
commands while rendering is paused can overflow the render command buffer.

<span id="morph-targets"></span>
<span id="bones--skeletal-animation"></span>

### Drive morph targets or bones

For facial expressions or other blends you control yourself, call
`asset.getMorphTargetSets()` to find the model's targets. Use `setWeightAt`
on one of those sets to change a target by index.

```dart
final targets = await asset.getMorphTargetSets();
if (targets.isNotEmpty && targets.first.targets.isNotEmpty) {
  await targets.first.setWeightAt(0, 0.5);
}
```

For bone animations or direct bone transforms, see the
[animation sample](https://github.com/nmfisher/thermion/tree/develop/examples/flutter/animations)
and the [ThermionAsset API](https://pub.dev/documentation/thermion_dart/latest/).
Attach an animation component with `addAnimationComponent()` if the asset needs one.

<span id="cleanup"></span>

## Release scene resources

Call `viewer.destroyAsset(asset)` when an asset is no longer needed. If you
destroy all assets with `viewer.destroyAssets()`, discard their old entity
handles too. Dispose of any material instances and textures you created.

If you supplied the viewer to `ThermionWidget(viewer: viewer)`, dispose of
it after removing the widget from the tree. `ThermionWidget.create` takes
care of this for a viewer created by its factory.

See the [complete Flutter viewer example](https://github.com/nmfisher/thermion/tree/develop/examples/flutter/viewer)
for a runnable project, or continue with [Light and style a scene](/materials/).
